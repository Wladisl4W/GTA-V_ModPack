# Разработка GTA V ModPack

## Быстрый старт

Рабочие исходники модов находятся в `Source Code/Plugins`. Для разработки нужны
Windows, Windows PowerShell 5.1, .NET SDK с поддержкой сборки net48, установленная
GTA V с Script Hook V, ScriptHookVDotNet3 и LemonUI.SHVDN3.

Создайте `modpack.local.json` по образцу `modpack.example.json` и укажите
`GameDirectory`. Локальный конфиг игнорируется Git. На текущем компьютере он уже
создан. Пути внутри репозитория определяются автоматически, рабочая папка терминала
не имеет значения.

Из корня репозитория:

```powershell
# Проверить ВСЕ плагины, ничего не копировать:
.\modpack.cmd Check

# Проверить и обновить Ready To Use и игру:
.\modpack.cmd

# То же с явным конфигом и временем ожидания:
.\modpack.cmd Update -Config "D:\configs\modpack.json" -TimeoutSeconds 45

# Проверить поведение загрузчика без GTA:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\test-reloader.ps1

# Проверить доставку в изолированной временной папке (после Release-сборки загрузчика):
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\test-update.ps1
```

Код возврата 0 означает успешное завершение команды; ненулевой код означает ошибку.
Тест доставки использует временную копию структуры проекта и имитацию записи в
лог: он не запускает GTA и не изменяет установленные игровые файлы.
Если файлы уже совпадают, команда сообщает об этом и не заявляет о новой
перезагрузке. Если изменился только пакет Ready To Use, подтверждение игры не требуется.

## Однократное обновление загрузчика

Для команды Update нужен Reloader с файловой версией 2.0.0.0 или новее.
Это версия загрузчика, а не номер релиза ModPack. Старый загрузчик не поддерживает
блокировку пакетной доставки и отпечаток исходников в логе.

1. Закройте GTA V.
2. Соберите загрузчик:
   `dotnet build "Source Code\Reloader\Reloader.csproj" -c Release`.
3. Замените `GTA V\scripts\Reloader.dll` файлом
   `Source Code\Reloader\bin\Release\net48\Reloader.dll`.
4. Запустите игру. В `scripts\ReloaderPlugins\Reloader.log` после загрузки
   должна появиться строка `Reload OK: <отпечаток>`.

Обычная команда Update никогда не копирует DLL. Сборка загрузчика тоже не устанавливает
его в игру. Замена DLL при работающей игре не обновит уже загруженный код.

## Как работает проверка и доставка

Проверка и живой загрузчик используют один `PluginCompiler.cs`: CodeDOM из
.NET Framework, одинаковый набор системных ссылок и поиск библиотек в игровой
папке scripts и её ReloaderPlugins. Файлы `*.cs` берутся из верхнего уровня Plugins;
имена с начальным `_` исключены, кроме `_PluginInterface.cs`.
Все плагины компилируются вместе. Современный синтаксис, который понимает SDK,
может не поддерживаться живым CodeDOM: окончательная проверка модов — команда Check.

Update сначала компилирует исходники. При ошибке ничего не копируется.
Затем проверяет отсутствие лишних `.cs` в целевых папках: неизвестные или устаревшие
файлы нужно разобрать вручную, автоматического удаления нет.
Команда копирует только изменённые `.cs`, проверяет SHA-256 и общий отпечаток.
На время копирования создаётся `.deploy.lock`; новый Reloader откладывает перезагрузку.
При обычной ошибке копирования восстанавливаются предыдущие файлы.
Не редактируйте исходники параллельно с Update.

После доставки проверяются только новые байты лога и точное совпадение отпечатка.
Ожидание по умолчанию — 30 секунд. Тайм-аут означает: файлы доставлены, запуск
в игре не подтверждён. Он не откатывает уже скопированные файлы.
Запустите или снимите игру с паузы, нажмите F5 и проверьте лог.
Повторная команда без изменений не запускает повторную перезагрузку.

Если процесс доставки был принудительно завершён, может остаться `.deploy.lock`.
Убедитесь, что никакая доставка не выполняется, проверьте целостность файлов,
удалите этот конкретный файл из игровой Plugins и повторите Update/F5.
Блокировка не имеет автоматического срока истечения.

## Безопасная перезагрузка

Старая версия продолжает работать, пока новая компилируется. Ошибка компиляции,
чтения исходников или получения типов не вызывает OnAbort старых плагинов.
Предупреждения сохраняются в `compile_errors.txt`, но допускают загрузку.
После чистой компиляции устаревший файл диагностики удаляется.

После успешной компиляции старые плагины получают OnAbort и запускаются новые.
Если конструктор или OnStart нового плагина бросает исключение, экземпляр очищается
через OnAbort и не получает OnTick. Лог содержит `Reload incomplete`.
Это не транзакционный откат игрового мира: ошибка запуска после остановки старой
версии не восстанавливает её. Исключения, которые сам плагин проглотил внутри
OnStart, загрузчик обнаружить не может.

OnTick и игровые native-вызовы остаются в игровом потоке. Компиляция синхронная
и может кратко приостановить кадры. Перезагрузка заменяет весь набор плагинов;
временное состояние и открытые меню могут сбрасываться.

## Как добавить или улучшить мод

1. Добавьте класс с публичным конструктором без параметров и `IGtaPlugin`.
2. В OnStart загрузите настройки, создайте меню и зарегистрируйте обработчики.
3. В OnTick обновляйте интерфейс и активную механику. Тяжёлые сканирования
   выполняйте по интервалу; не блокируйте поток ожиданием загрузки модели.
4. В OnKeyDown обрабатывайте клавишу меню. Проверьте занятые клавиши:
   `rg -n "Keys\." "Source Code\Plugins"`.
5. В OnAbort освободите созданные сущности и камеру, восстановите изменённые
   параметры игрока и мира, сохраните настройки. Очистка должна выдерживать
   повторный вызов и частично завершённую инициализацию.
6. Выполните Check, затем Update и воспроизведите поведение в игре.

Не меняйте значения существующих enum в сохранениях без миграции.
Новым JSON-полям задавайте совместимые значения по умолчанию.
Не удаляйте чужие сущности и не сбрасывайте глобальную физику без учёта других модов.
Взаимодействие RemoveDroppedPeds, SharkRider и камеры требует отдельной игровой
проверки: успешная компиляция не подтверждает правильность поведения.

Перед завершением изменения проверяйте: включение/выключение, смерть или смену
персонажа, потерю целевой сущности, открытое меню, F5 во время активного эффекта
и повторный запуск. Для камеры дополнительно проверяйте старые пути, поворот
на 180 градусов, FOV и резкий возврат с последней ноды на первую.

## Диагностика и релизы

### Режим разработчика

`Ctrl+F10` открывает меню разработчика. «Режим разработчика» включает подробный
лог; «Показывать панель» отдельно выводит владельца управления, состояния камеры
и акулы и последние пять событий. Обе опции изначально выключены. Режим логирования
сохраняется, но панель всегда скрывается после запуска и F5. Если комбинация
используется сторонним модом, это не отслеживается автоматически.

Лог: `scripts/ReloaderPlugins/Development.log`. Одинаковые события допускаются
раз в три секунды; максимальный размер — 5 МБ, одна предыдущая копия хранится
в `Development.log.previous`. Панель обновляет текст пять раз в секунду.
Обычные ошибки плагинов записываются в прежние логи независимо от этого режима.

Для камеры ищите `Damage ped` (способ обнаружения), `Target already followed`,
`No fresh eligible damage target` и `Blocked by`. Для акулы отображаются состояния
Spawning, Approaching, Mounting, Riding, AttackAligning, BiteScene и события остановки.
После отклонённой автоматической посадки/укуса нужно выйти из воды или отойти от
акулы дальше шести метров и подойти заново. Отклонённый удар не ставится в очередь.

### Владение управлением

Камера и акула получают общий `ControlSession` до вмешательства в игрока.
Текущий эффект имеет приоритет; конфликтующий ручной запуск показывает причину,
автоматический отказ только логируется. Выходное затемнение камеры тоже занимает
управление. Обычные меню и механики NPC продолжают работать.

При завершении восстанавливается снимок заморозки, видимости, коллизии и неуязвимости
исходного персонажа. Для времени сохраняется фактический TimeScale; для изменённой
гравитации возвращается штатный preset 0, поскольку API не предоставляет надёжного
чтения предыдущего preset. Координация распространяется только на моды этого пака:
состояние Menyoo и других установленных модов автоматически не согласуется.
При смерти/смене персонажа эффект завершается; снимок не применяется к новому педу.

### Резервные сохранения

Пути камеры, настройки SharkRider, RemoveDroppedPeds, RainbowPaint и его исключения,
DevelopmentSettings и INI MenyooStreamer используют `SafeFiles`.
При повторной успешной записи предыдущая исправная версия сохраняется как `.bak`.
Запись идёт через временный файл и атомарную замену. Старые форматы не меняются.

Если основной файл повреждён, исправная `.bak` восстанавливается автоматически;
повреждённый оригинал остаётся под именем `.corrupt-<id>`. Если повреждены обе копии,
мод может использовать стандартные настройки в памяти, но сохранение поверх
повреждённых файлов блокируется проверкой содержимого. Восстановите валидный основной
файл вручную или явно удалите обе копии, если они больше не нужны. Затем повторите
сохранение. Не удаляйте файлы, если ещё рассчитываете восстановить данные.

Переименование пути сначала записывает новый файл и только после успеха удаляет старый.
Существующий путь назначения не перезаписывается. При удалении пути его резервная
копия также удаляется. XML-миграция не заменяет существующий JSON; успешно перенесённый
XML остаётся архивом `.xml.archived-<id>`. Архивы и повреждённые копии не показываются
в меню и могут быть убраны вручную после проверки данных.

Для проверки общих сервисов без игры:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\test-modpack.ps1
```

Эти тесты используют имитацию GTA API для владения управлением и реальные временные
файлы для сохранений. Они не проверяют анимации, физику и затемнения в запущенной GTA.

- `Reloader.log`: компиляция, запуск, ошибки жизненного цикла и отпечаток.
- `compile_errors.txt`: ошибки и предупреждения компилятора с файлами и строками.
- `PluginErrors.log`: общий ограниченный по частоте лог некоторых плагинов.
- Остальные плагины могут вести собственные логи в ReloaderPlugins.

Обычный `dotnet build Source Code/Reloader/Reloader.csproj` проверяет только
загрузчик. Для модов обязательно выполняйте Check. `Source Code/build.bat`
сначала запускает Check, затем собирает загрузчик.

Перед релизом проверьте синхронность исходников и Ready To Use, игровые сценарии
и совместимость сохранений. Архив `ModPack-Plugins-X.Y.zip` содержит прямое
содержимое `Ready To Use/ReloaderPlugins/Plugins`, без родительской папки Plugins
и без Reloader.dll. Обновление загрузчика распространяйте отдельно с инструкцией
закрыть игру. Пользовательские JSON-настройки не включайте в обновление.
Релиз и отправка в GitHub не входят в Check/Update.

Подробности отдельных модов и ранее принятые решения: [MODPACK_DEVELOPMENT.md](MODPACK_DEVELOPMENT.md).
